# 사이트 기기 승인

이 변경은 웹 배포 포털에 `xrt_site_access/v1` 접근 계약을 추가한다. 연구 API의 기기 등록, 승인된 ONNX 계약, 데스크톱 설치 파일 0.6.4의 바이트·해시는 바뀌지 않는다.

## 사용자와 관리자

처음 방문하면 `/access`에서 이름, 소속·연락처, 기기 이름을 제출한다. 서버는 브라우저 User-Agent와 platform 정보를 참고 정보로 보관한다. 하드웨어 일련번호나 MAC을 읽거나 신뢰하지 않는다. 관리자는 `/admin/site-devices`에서 기존 관리자 계정으로 로그인해 실제 사용자와 소속을 확인하고 사유를 남겨 승인·거절한다. 승인된 기기는 가이드와 설치 파일·해당 소스를 다운로드한다. 이후 권한 철회도 같은 화면에서 처리한다.

승인 단위는 물리 PC가 아니라 브라우저 프로필에 저장된 384-bit 임의 기기 키다. HTTPS Secure / HttpOnly / SameSite=Strict / Path=/ 쿠키에만 저장하며 서버에는 SHA-256 다이제스트만 남긴다. 쿠키 삭제·새 브라우저·요청 후 180일 만료 시 재요청한다. 키 탈취 자체를 막는 하드웨어 증명 기능은 아니다. 민감한 사용자 정보가 있으므로 승인 목록은 관리자만 열 수 있다.

## 경계와 호환성

- Nginx는 사이트 문서 요청마다 portal 승인 검사를 호출하며, 거절 시 요청 화면으로 보낸다. 접근 요청·관리자 로그인 화면과 그 공용 정적 부트스트랩 자원은 익명 접근이 가능하다. 정적 번들에는 비밀값이나 접근 권한이 없다.
- portal 자체도 가이드(공개 표시된 가이드 포함), 이미지, 릴리스 목록, EXE/소스/Range 다운로드마다 승인을 검사한다. Nginx를 우회해 portal에 직접 요청해도 승인 전에는 403이다. 기존 `/public` URL은 자료 공개 분류이며 익명 접근 허용을 뜻하지 않는다.
- 관리자 인증은 기존 upstream ADMIN 검사를 유지한다. 미등록 브라우저도 관리자 로그인으로 승인을 처리할 수 있다. 일반 연구원 로그인이나 임의 Authorization 헤더는 사이트 승인 대체 수단이 아니다.
- 기존 관리자 쿠키를 Path=/로 전환하고 로그인·로그아웃 시 이전 /portal-api 쿠키를 삭제한다. 기존 세션이 있다면 한 번 다시 로그인하면 된다.
- 기존 0.6.4 이하 데스크톱의 **익명 자동 업데이트 조회·다운로드는 이제 403**이다. 우회 허용은 두지 않는다. 승인된 브라우저에서 새 설치 파일을 받아 업그레이드한다. 로컬 분석과 기존 연구 API 동기화 인증에는 영향이 없다. 자동 업데이트 재연결에는 별도의 앱 자격 증명 계약과 새 설치 파일이 필요하다.
- `/api/v1/` 연구 서비스는 원래의 연구 기기 자격 증명·프로젝트 권한을 유지한다. 웹 승인 쿠키로 연구 데이터에 접근할 수 없다.
- 릴리스 형식 `xrt_app_release/v1`, EXE/소스 해시와 기존 다운로드 URL은 유지된다. URL을 아는 것만으로는 다운로드 권한이 생기지 않는다.

## 서버 저장과 운영

기존 portal SQLite에 site_devices와 site_request_limits를 추가한다. 비밀번호·세션·릴리스 레코드를 덮어쓰지 않는다. 기기 상태 변경은 revision으로 충돌을 검출하며 감사 기록과 같은 트랜잭션에 저장한다. 동일 쿠키의 반복 요청은 기존 상태만 반환한다. 새 요청은 서버가 관찰한 연결 주소 해시별 30건/시간, 전체 200건/시간으로 제한한다. 전달 헤더를 신뢰하지 않으므로 프록시 뒤 사용자는 같은 제한을 공유할 수 있다. 제한은 재시작 후에도 유지된다.

승인 검사와 응답은 캐시하지 않는다. 철회·만료 후 새 요청부터 거절하며 이미 시작된 파일 전송이나 이전에 다운로드한 파일을 회수하지는 않는다. 관리자 목록은 최신 1,000건 범위에서 대기 요청을 우선 표시한다. 관리자 장애 시 일반 승인 기기는 저장된 승인으로 이용할 수 있지만 관리자 인증은 실패 시 닫힌 상태를 유지한다.

배포 전 SQLite 온라인 백업과 현재 이미지 태그를 보존한다. 구 이미지로 롤백하면 이 접근 제한도 제거되므로 일반 장애 대응은 승인 경로를 점검하거나 차단 상태를 유지한 채 새 이미지로 복구한다. 외부에 기기 키, 관리자 자격 증명, 실제 데이터 파일을 게시하지 않는다.

## 확인

portal 테스트는 미승인/대기/거절/철회/만료, 직접 다운로드와 Range, 관리자 복구 경로, CSRF/Origin, 다이제스트 보관, 중복 요청, 영속 요청 제한을 검증한다. 웹 테스트는 승인 전 화면 차단, 요청 정보와 처리 사유, CSRF 및 revision 전송을 검증한다. 가이드 왼쪽 목록은 데스크톱에서 내부 스크롤과 overscroll containment를 사용하며 작은 화면에서는 기존 가로 작업 선택을 유지한다.
