# #152: 연속 결함 추적과 후보 검토 화면

## 증상과 원인

TIFF에서 가느다란 결함을 선택한 뒤 정상적으로 길어져도 `연결 모호`로 중단됐다. 기존 구현은 각 페이지의 면적과 길이를 첫 선택 페이지와 계속 비교했다. 시작점이 결함 끝의 짧은 조각이면 정상적인 성장도 병합으로 판정됐다. 거리 변환에 기반한 분할도 굵기가 달라지는 한 선을 여러 조각으로 나눌 수 있었다.

BPD는 별도의 국소 대비 윤곽을 만들고 있었지만, 분석 결과를 불변 객체로 보관하는 과정에서 좌표 배열이 중첩 튜플로 바뀌었다. QML에 전달할 때 이를 배열로 복원하지 않아 Canvas에서 윤곽을 사용할 수 없었다. 기존의 128px 읽기 범위와 밝은 중심점 우선 선택도 긴 BPD 전체를 표현하기에 부족했다.

전체 이미지에 표시하던 숫자 원형 묶음은 후보 유형을 가리고 시각적 밀도를 높였다. 결과 패널은 탐색 설정, 일괄 선택, 후보 정보, 신고를 한꺼번에 노출해 실제 검토 목록에 쓸 공간이 줄었다.

## 추적 방식

1. 원본 픽셀에서 추출한 연결 성분과 이전 페이지의 실제 마스크를 사용한다.
2. 골격의 길이와 폭으로 선형 구조인지 판단한다. 폭은 거리 변환의 85백분위수로 측정해 큰 덩어리를 가느다란 선으로 오인하는 경우를 줄인다.
3. 교차점에서는 이전 마스크와 겹치는 가지를 시작으로 국소 접선의 연속성을 비교한다. 직선만 허용하는 규칙이 아니므로 단일 곡선은 굽어도 이어진다.
4. 두 진행 방향이 비슷한 실제 분기는 자동으로 확정하지 않는다. 반면 선 폭 안의 작은 밝기 홈이 만든 두 평행 골격은 관측된 두 부분을 유지한다. 홈을 메우거나 없는 픽셀을 추가하지 않는다.
5. 선택한 골격과 다른 골격까지의 거리로 관측된 전경만 분리한다. 원래 픽셀에 없는 연결 다리를 만들지 않는다.
6. 첫 페이지의 작은 면적과 비교하는 제한을 제거하고 이전 페이지의 폭·형태·크기와 비교한다. 읽기, 페이지 수, 메시, 메모리 제한 및 취소 처리는 유지한다.

`연결 없음`, `진행 방향 후보가 비슷함`, `주변 구조와 접촉`을 화면에서 구분한다. 사용자는 같은 결함 지정, 다른 결함 제외, 페이지 건너뛰기로 판단에 개입할 수 있다. 어두운 선이 사라지는 구간을 무조건 연결하는 기능은 아니다.

## BPD 영역과 계약

- BPD 분류 후보에 대해 128→256→512→1024px로 원본 읽기 범위를 확대한다. ROI 및 이미지 범위를 벗어나지 않는다.
- 가까운 길쭉한 구조의 길이와 대비 강도를 함께 비교한다. 밝은 중심점이나 어두운 선 옆의 약한 밝기 테두리만 선택하는 문제를 회귀 검사한다.
- 결과 윤곽은 원본 좌표의 다각형이다. 경계에 닿으면 `region_clipped`로 표시하고 완전한 윤곽이라고 주장하지 않는다.
- 실행 중 결과, 완료 결과, 저장 프로젝트 모두 QML에 중첩 리스트로 전달한다.
- BPD는 영역 테두리로 그린다. 윤곽이 없는 과거 결과는 위치 십자로 표시하고 상세 화면에서 재분석 필요성을 알린다.
- 이는 **원본 대비로 만든 영역 제안**이다. ONNX 모델을 세그멘테이션 모델로 바꾼 것이 아니며 물리적 결함의 정답 경계도 아니다.
- 모델 해시, 모델 입력 RGB 128px, 클래스 순서, 점수, `POINT` 출력 계약, 신고 서버 API와 저장 스키마 버전은 변경하지 않는다. 영역 정보는 기존 선택적 메타데이터에 추가된다. ML 및 데이터 도구 저장소는 수정하지 않는다.

## 화면 구성

전체 이미지에서는 TED·TSD를 작은 클래스 색상 표시로, BPD를 테두리로 보여준다. 숫자 원형 묶음과 윤곽 위의 중복 원은 제거한다. 선택 후보만 강조하고 기존 표시 투명도와 레이어 설정을 존중한다.

결과 패널은 후보 수와 클래스 필터 → 현재 영역 → 주변 후보 목록 → 후보 이동 → 확인·보류·신고 순서다. 썸네일을 크게 하고 체크박스는 여러 개 선택 모드에서만 보인다. 검토 방식과 영역 크기는 별도 설정 창으로 옮겨 작은 창에서 목록과 하단 버튼이 밀려나지 않게 한다. 기존 전체 지도와 확대 범위 표시, 신고 대기열, 내보내기는 유지한다. 모델 점수와 사람의 확인 여부를 구분한다.

## 검증 근거와 한계

- 합성 TIFF: 짧은 끝부분의 성장, 다음 페이지 교차점, 동일한 Y 분기, 작은 밝기 홈, 굽은 선, 실제 전경에만 속하는 마스크를 검사한다.
- 합성 RGB: 밝은 점이 붙은 긴 BPD가 128px를 넘어 이어지는지, 약한 반대 극성 테두리를 선택하지 않는지, ROI 경계 표시와 원본 불변성을 검사한다.
- 실제 QML: 불변 메타데이터의 다각형이 자바스크립트 배열로 전달되는지, 필터·선택·이동·점수 상세가 유지되는지, 1100×700에서 필수 버튼과 설정 창이 화면 안에 있는지 검사한다.
- 사용자 TIFF의 중심 선을 같은 시작점에서 비교한 로컬 재현: 기존 UI 페이지 31~51, 21개 페이지에서 수정 후 31~82, 52개 페이지로 이어졌다. 약해지는 끝부분은 자동 확정하지 않았다. 이것은 특정 재현 사례의 결과이며 전체 데이터 추적 정확도가 아니다.
- 사용자 RGB 이미지의 로컬 추론: 총 2,946개(BPD 245, TED 1,398, TSD 1,303)는 유지됐고 BPD 245개에 표시 가능한 영역 제안이 만들어졌다. 최종 실행에서 읽기 경계에 닿은 제안은 0개였다. 정답 윤곽과 비교한 성능 수치가 아니다.
- 1920×1080 및 1100×700 실제 QML 렌더링을 확인했다. Basic과 배포판의 FluentWinUI3 스타일 모두에서 QML 경고 없이 확인했다. 로컬 캡처는 offscreen이므로 운영 Windows의 GPU 실사용 검증을 대체하지 않는다.
- 원본 연구 이미지, 모델, 로컬 캡처 및 좌표별 상세 로그는 Git에 넣지 않는다. 신고 데이터는 검증 중 전송하지 않는다.

정량적인 추적·분할 정확도 평가는 전문가가 확인한 페이지 간 대응과 정답 윤곽이 있어야 가능하다. 현재 수정은 조기 중단 및 표시 결함의 재현 사례를 해결하며, 모든 교차 구조를 물리적으로 식별했다고 주장하지 않는다.


## 0.6.1 설치판 배포

사용자 승인에 따라 이 수정은 0.6.1 Windows 설치판으로 배포한다. 기존 0.6.0과 같은 BETA 채널을 사용하며 설치판·프로그램·패키지 버전을 함께 변경한다. 전체 CI와 새 frozen runtime, 별도 AppId 설치, 원본 JPG/TIFF 읽기 검증을 통과한 뒤 포털에 게시한다. 게시 후 기존 앱의 업데이트 조회 및 전체 설치 파일 SHA-256 검증으로 전달을 확인한다. 서버 API·DB 스키마 변경은 없으며 기존 릴리스와 사용자 데이터를 보존한다.
