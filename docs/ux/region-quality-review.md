# 영역별 결함 검토와 확대 품질 개선

결함 후보를 영역별로 검토하면서 주변 후보와 전체 이미지의 현재 위치를 함께 확인할 수 있다. Wafer Map은 로딩 시 원본 해상도를 포함한 이미지 계층을 준비하고, 이동할 때 이미 만든 타일을 재사용한다. 선택 결함 3D는 얇은 곡선을 지나치게 잘게 나누던 문제를 수정하고 직접 연결·제외·건너뛰기를 제공한다.

## 작업 순서와 적용 범위

| 단계 | 적용 내용 |
| --- | --- |
| 0 | 실행 스크립트가 가리키는 최신 소스와 기존 변경 확인 |
| 1 | Wafer Map 원본 계층 사전 준비, 타일 재사용, 메모리·디스크 한도, 실패 건수와 재시도 |
| 2 | 검출 후보와 사람이 확인한 기록 구분, 후보 한도·분류 제외 사유 표시 |
| 3 | 영역별·우선순위·분산 순서·원본 전체 탐색, 주변 후보 썸네일, 확인·보류·다중 선택 |
| 4 | 전체 이미지 지도, 현재 화면 사각형, 선택 위치, 검토 범위, 지도 이동과 이전 확대 복귀 |
| 5 | 신고 대기열, 묶음 신고, 선택 이미지 첨부, 전송 미리보기, 재전송 중복 방지 |
| 6 | 곡선 분할 개선, 페이지 연결 보정, 의심 분기 표시, 3D 자동 화면 맞춤 |
| 7 | 내용에 맞는 업데이트 창, 분석 상세 정보 펼치기, 작은 화면 도구·패널·메뉴 배치 |

## 영역별 검토 사용법

결과 패널의 기본 단위는 영역이다. 같은 영역에서 후보 화살표를 누르면 선택만 옮겨 주변 맥락을 유지한다. 다른 영역으로 이동하거나 선택 지점이 화면 밖에 있으면 해당 영역을 보여준다. 256·512·1024 원본 픽셀 단위로 영역을 바꿀 수 있다. 작은 창에서는 ‘검토 설정’을 펼쳐 모드와 크기를 변경한다.

‘우선 검토’는 낮은 모델 점수의 후보가 많은 영역부터 보여준다. ‘분산 표본 순서’는 모든 영역을 결정적인 순서로 흩어 배치하며 통계적 대표성이나 미검토 영역의 품질을 보증하지 않는다. ‘원본 전체 훑기’는 후보가 없는 영역도 포함하여 누락 확인을 돕는다. ‘개별 후보’ 모드는 기존 한 개씩 이동하는 방식이다.

체크한 후보에 확인 또는 보류를 적용하며 선택이 없으면 현재 후보에 적용한다. 열어본 영역 수와 직접 확인한 후보 수를 구분한다. 확인 기록은 분석 실행별로 기기에 저장된다. 이 기록은 기존 검수 데이터의 승인이나 학습 정답으로 자동 변환되지 않는다. 필터로 일부 종류만 확인해도 영역 전체를 확인한 것으로 표시하지 않는다.

전체 지도에서 사각형은 현재 화면, 노란 점은 선택 후보를 나타낸다. 지도를 클릭하거나 끌어 이동한다. 전체 보기를 사용한 뒤 이전 확대 위치로 돌아갈 수 있다. 축소 화면의 매우 많은 표식은 밀집도 수로 묶고 확대하면 개별 후보를 보여준다.

## Wafer Map 해상도와 캐시

원본 디코딩 픽셀은 비트 깊이를 유지한 배열로 보관한다. 축소 보기에는 미리 만든 계층을 사용하고 확대 시 해당 원본 영역을 사용한다. 연결된 사진을 이동할 때 JPEG 전체 디코딩이나 이미지 정합을 다시 실행하지 않는다. 화면 합성과 표시용 텍스처 갱신은 필요하므로 모든 화면 작업이 계산 없이 끝나는 구조는 아니다.

기본 캐시는 임시 폴더의 `sic-xrt-wafer-levels-v1`이며 `SIC_XRT_WAFER_CACHE`로 위치를 지정할 수 있다. 원본 경로·크기·수정 시각·페이지·캐시 버전으로 재사용 여부를 결정한다. 원본 한 장의 계층은 최대 16 GiB, 캐시 디렉터리는 최대 64 GiB, 화면 타일 메모리는 64 MiB로 제한한다. 화면 출력은 최대 16,777,216픽셀이다. 한도를 넘으면 오류를 표시하며 원본을 몰래 낮은 화질로 대체하지 않는다. 캐시 정리가 필요하면 앱을 종료한 뒤 지정 캐시 폴더만 정리한다.

실제 12,349 × 12,273 JPEG 한 장의 로컬 측정에서 준비 4.94초, 캐시 재개방 0.039초, 재개방 후 추가 디코딩 0회를 확인했다. 선택한 1:1 출력 영역은 디코딩 원본 픽셀과 동일했다. 준비된 화면 이동의 CPU 합성은 첫 타일 135ms, 뒤의 일곱 이동은 약 4.3–26.9ms였다. 이 수치는 해당 파일의 합성 측정이며 16장 전체 지도나 입력부터 화면 표시까지의 프레임 시간 측정은 아니다.

## 신고 저장과 서버 계약

체크한 후보를 묶어 신고 대기열에 추가한다. 한 신고는 최대 500개 후보를 포함한다. 사유는 결함 아님·종류·위치·영역 수정·중복·누락·기타다. 중복 신고는 후보 2개 이상, 누락 신고는 ROI가 필요하다. 누락 신고에는 기존 후보를 포함하지 않는다.

선택 사항인 이미지 첨부는 선택 ROI 또는 첫 후보 중심의 상세 128픽셀, 주변 512픽셀 PNG 두 장이다. 여러 후보를 선택해도 모든 원본이나 후보별 이미지를 자동 첨부하지 않는다. 대기열에서 서버 주소, 사유, 메모, 좌표와 ROI, 첨부 이미지를 미리 보고 명시적으로 전송한다. 실패 건은 같은 신고 ID와 내용을 유지해 재시도한다. 첫 전송 시도 후에는 다른 서버로 자동 전환하지 않는다.

새 서버 계약은 인증이 필요한 `POST /api/v1/reports`의 `xrt_correction/v1`이다. 정확한 필드와 검증은 `sync/report_queue.py::validate_report`에 있다. 원본 식별 정보는 SHA-256·크기·dtype·페이지이며 로컬 파일 경로는 전송하지 않는다. ROI는 원본 픽셀 좌표이고 다각형 경로도 보존한다. 기존 로컬 `xrt_user_report/v1` 파일은 유지한다. 기존 프로젝트 동기화 형식은 변경하지 않는다.

서버는 사용자·기기·신고 ID별로 내용을 저장하고 `report_id`, 정규화된 payload의 `payload_hash`, `status=ACKNOWLEDGED`를 반환한다. 같은 ID와 다른 내용은 409, 잘못된 형식은 422, 저장 장애는 503이다. 클라이언트는 정확한 응답 해시가 일치해야 전송 완료로 기록한다. 모든 신고의 승인 상태는 `UNVERIFIED`다.

이 변경을 사용하는 서버에도 새 엔드포인트를 배포해야 한다. 구버전 서버의 404 응답은 실패 건으로 남고 대기열은 보존된다. 서버 배포와 실제 연구 데이터 업로드는 이번 로컬 검증에 포함하지 않는다. 인증·재시도 검사는 합성 데이터와 로컬 테스트 클라이언트로 수행했다.

## 선택 결함 3D

두께가 조금씩 변하는 얇은 선에서 거리 최댓값마다 영역을 쪼개던 동작을 연결된 중심부 기준으로 바꾸었다. 길지만 얇은 곡선을 받아들이면서 두꺼운 큰 영역·분기·모호한 합류에 대한 제한은 유지한다. ‘같은 결함 연결’로 다른 페이지의 대응 지점을 지정하고, 제외 또는 페이지 건너뛰기로 보정할 수 있다. 건너뛴 페이지의 결함 픽셀은 만들어 넣지 않는다.

실제 158페이지 TIFF의 한 U자 곡선 지점은 변경 전 1페이지 조각에서 변경 후 53페이지로 추적 범위가 늘었다. 교차 선이 연결될 수 있으므로 분기 의심 페이지를 표시하며 자동 합류를 보수적으로 중단한다. 이 사례는 추적 동작 비교이고 결함 탐지율이나 정확도 측정이 아니다. 정답 마스크를 갖춘 실제 평가와 모델 재학습은 별도의 데이터·모델 평가 작업이 필요하다. 물리적인 깊이 간격을 모르면 페이지 순서만 사용한다.

## 검증 방법

원본 픽셀 일치, 캐시 재사용, 페이지 연결·건너뛰기, 지역 경계와 확인 상태, 신고 응답·재시도, 실제 Qt 입력 이벤트와 작은 창·고 DPI 배치를 검사한다. Windows에서는 짧은 임시 경로를 쓰고 ImageJ 런타임 경로를 설정한다. Qt 상태가 다른 검사에 영향을 주지 않도록 테스트 파일별 새 프로세스에서 실행할 수 있다.

실제 연구 이미지와 그 잘라낸 결과는 Git에 포함하지 않는다. UI 캡처의 후보 데이터는 레이아웃을 확인하기 위한 합성 데이터다.

검증 집계는 64개 테스트 파일 기준 818개 통과, 12개 건너뜀이다. 고 DPI 검사는 100%·125%·150%·200%에서 통과했다. 전체를 한 프로세스에서 실행한 시도는 Qt 접근 위반으로 종료되어 파일별 프로세스로 분리해 검증했다. 원래 실행 폴더의 ImageJ 런타임을 연결한 뒤 관련 기능도 재검증했다. 새 신고 HTTP 검사는 별도 PostgreSQL이나 운영 서버에 접속하지 않고 인증 의존성을 대체한 로컬 테스트 클라이언트로 검사했다.
