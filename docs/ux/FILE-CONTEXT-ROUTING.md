# 파일 형식에 따른 Context 자동 전환

Issue: [#92](https://github.com/CrystalVision-Lab/sic-xrt-analyzer/issues/92)

## 동작

파일 선택, 드롭, 최근 파일 열기가 성공한 뒤 디코더가 확인한 형식으로 전환한다.

| 실제 형식 | 작업 영역 | 우측 패널 | 표시 도구 |
| --- | --- | --- | --- |
| JPG/JPEG | 이미지 분석 | 접힘 | 넓은 Viewer, 상단 분석하기/패널 메뉴 |
| 단일 페이지 TIFF | 이미지 분석 | 뷰어·스택 열림 | 밝기·대비, 기존 Viewer 도구 |
| 여러 페이지 TIFF | 이미지 분석 | 뷰어·스택 열림 | 페이지 이동, 밝기·대비, 기존 스택 도구 |

`.tif`/`.tiff`/`.jpg`/`.jpeg`의 대소문자를 지원한다. 이름과 내용이 다르면
디코더의 실제 형식을 우선한다. 왼쪽 3D 작업 영역으로 이동하지 않으며,
페이지 순서나 ImageJ frames를 물리 공간 Z축으로 해석하지 않는다.

**패널 ▾**로 다른 Context를 선택하거나 **×**로 접을 수 있다. 이후 페이지 이동,
로딩 진행, 열기 실패는 선택한 Context를 덮어쓰지 않는다. ImageJ 작업 복사본도
자동 전환의 대상에서 제외한다. 분석하기는 기존 분석 준비 화면을 열며 추론을
자동으로 시작하지 않는다. 화면 배치 초기화는 넓은 기본 배치를 복원한다.

## 변경 범위

파일 열기 성공 이벤트에서 `OPEN_TIFF`를 `viewer`에 연결했다. 표시 데이터,
원본 좌표/ROI, 분석 입력, 모델/ONNX 결과, ImageJ/Fiji, Export, Native Dialog는
변경하지 않았다. 원본 이미지와 `sources/`, 사용자 AGENTS.md는 수정하지 않았다.

## 검증

새 자동 검사 8개는 uint16 단일/다중 TIFF, 대문자 확장자, JPEG, 파일명과 실제
형식 불일치, 원본 SHA256 보존, 페이지 변경 및 열기 실패 후 수동 Context 보존을
확인한다. 기존 UI·분석·ROI·스택 검사를 함께 실행한다. 합성 파일과 QTest를
사용하며 실제 XRT 성능 및 물리 마우스 Acceptance를 다시 측정하는 작업은 아니다.
최종 검사 결과는 연결 PR에 기록한다.
