# 연결 결함 3D · 웨이퍼 모자이크 · 자동 업데이트 — #131

## 사용

- 여러 페이지 흑백 TIFF를 열고 **결함 3D** → 원하는 검은 결함 안쪽을 클릭한다. Fit에서 너무 작으면 먼저 확대한다. 자동으로 앞뒤 페이지를 추적하고 배경 없는 표면을 연다.
- 3D에서는 드래그 회전, 우클릭 드래그 이동, 휠 확대, 더블클릭 화면 맞춤을 사용한다. **다시 선택**은 2D로 돌아간다. 정상 화면에는 페이지 슬라이더·단면 탭이 없다.
- Wafer Map → **폴더 선택**. 촬영 구역별 큰 합성 사진이 함께 있는 상위 폴더는 전체 웨이퍼를 우선 연다. 촬영 전·후와 배율은 별도 묶음이다. 위쪽 선택으로 상세 구역도 볼 수 있다. 더블클릭하면 해당 원본을 연다.
- 새 버전의 **업데이트**는 다운로드·검증 후 저장 확인을 거쳐 앱을 종료하고 같은 위치에 설치하여 다시 실행한다. 사용자가 취소하면 종료하지 않는다. 설치 앱이 아닌 Python 개발 실행에서는 기존 제한을 유지한다.
- 기존 0.2.0 클라이언트의 **종료 후 설치**도 새 설치 파일이 처리한다. SHA 이름의 app-updates 캐시, 기존 사용자 설치 등록, 파일 SHA를 확인한 뒤 보조 프로세스가 무인 설치·재실행한다. 처음 설치할 때에는 일반 설치 화면을 유지한다.

## 표시 계약

`stack3d/defect.py`는 원본 숫자형 흑백 픽셀의 국소 어두운 대비를 구한다. 완만한 조명 기울기와 밝은 띠를 배경 추정에서 제외한다. 클릭한 8-연결 성분에서 출발하여 인접 페이지의 실제 26-이웃 접촉 성분만 양방향으로 추적한다. 빈 페이지를 보간하거나 가장 가까운 다른 성분으로 건너뛰지 않는다. 급격히 커지는 합류에서는 멈추고 경고한다. 가지는 보존한다.

페이지는 하나의 TiffFile 핸들에서 한 번씩 디코딩하고 확대 탐색 때 재사용한다. 읽기·분할·Marching Cubes는 취소 가능한 Worker에서 수행한다. 파일 교체·닫기·취소는 요청 세대를 무효화한다. 같은 경로라도 파일 크기·mtime이 바뀌면 기존 mesh를 버린다. 재생성은 클릭했던 페이지를 사용한다.

원본 좌표의 페이지별 bit mask와 mesh를 별도로 보관한다. 원본은 쓰지 않는다. 페이지 디코딩 64 MiB, 추적 영역 한 변 4096, 압축 마스크 128 MiB, mesh용 dense occupancy 32 MiB, 면 400,000개가 상한이다. 필요하면 XY occupancy만 축소하며 원본 mask는 유지하고 간격을 표시한다. 페이지를 건너뛰지 않는다. 화면 좌표 정규화는 geometry 복사본에만 적용한다.

이는 **관측된 어두운 구조의 표시용 분할 제안**이다. 분할 정확도·전위 종류·물리적인 3D 연속성은 검증하지 않았다. 서로 닿은 별개 구조는 합쳐질 수 있으며 명암이 약한 구간에서 추적이 멈출 수 있다. Z 측정 근거가 없어 깊이 축은 페이지 순서이다. 실제 길이·체적·결함 판정으로 사용하지 않는다. 원본·ROI·분석 입력·ONNX 결과·검수·ImageJ 계약·기존 stack 데이터 API는 바꾸지 않는다.

## 웨이퍼 배치 근거

1. 폴더에 큰 합성 사진과 작은 원본 구역이 있으면 정규화 상관 매칭으로 위치를 확인하고 큰 합성 사진은 한 번만 표시한다.
2. 번호가 연속인 정사각 촬영 묶음은 행·열·뱀 순서 후보의 경계 오차가 무작위 순서보다 충분히 작을 때만 이어 붙인다. 원형 마스크를 씌우거나 누락 사진을 채우지 않는다.
3. 일반적인 겹침 촬영은 SIFT·RANSAC similarity와 실제 겹침·잔차·순환 일관성으로 배치한다. 근거가 없는 사진은 임의 격자로 배치하지 않고 오류를 표시한다.

표시는 최대 3072 px의 상대 모자이크이며 물리적인 Wafer 좌표·보정된 계측값이 아니다. 촬영 경계의 조명 차이와 작은 이음새가 남을 수 있다. 모든 원본이 정합 가능하다고 보장하지 않는다. 줌은 요청 완료 revision에서만 맞춤 처리하므로 상태 알림이나 줌 하한 도달로 초기 배율로 돌아가지 않는다.

## 업데이트 보조 프로그램

`installer/UpdateHandoff.cs`는 Windows .NET Framework 4.x의 csc.exe로 빌드한다. `build_windows_installer.py`가 컴파일하여 설치 파일 안에 포함한다. 별도의 .NET 다운로드·관리자 승격·shell 명령은 사용하지 않는다. 기존 setup 프로세스 종료를 기다리고 SHA를 재검증한 후 현재 사용자 설치 위치로 무인 실행한다. 로그는 app-updates 캐시에 보관한다. 강제 프로세스 종료·설정 삭제를 하지 않는다.
