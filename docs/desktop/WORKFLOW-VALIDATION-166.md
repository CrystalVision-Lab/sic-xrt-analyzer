# 연구 작업 흐름 개편 검증 (#166)

## 구현

- 설치 후 첫 실행에서 기기 ID 전달, 발급된 서버 주소/인증키 입력, 연결 확인 또는 로컬 사용을 선택한다. 파일 메뉴로 재진입할 수 있다. 인증키는 기존 OS Vault 계약을 사용하며 입력란은 닫을 때 비운다. 설치 프로그램에서 관리자의 웹 비밀번호를 받거나 기기 승인을 우회하지 않는다.
- 분포 색 농도 기본값을 최대 0.55에서 0.12로 낮추고 후보 위치를 함께 표시한다. 후보 강도/분포 농도를 조절할 수 있다. 제외 원인과 후보 한도를 표시하며 탐색 대비 12/8, 한도 3000/6000/10000을 명시적으로 선택한다.
- 3D 기본 화면은 확대 원본 + 위치 지도 + 크기 조절 가능한 3D 패널이다. 0.5/1/2배속은 프레임 대기/애니메이션만 조절하며 추적 입력과 마스크는 바꾸지 않는다. uint16 원본의 직교 비교는 선택 seed의 XY/page 위치로 시작한다.
- 앱 오프라인 가이드와 웹 가이드는 동일 JSON 내용을 사용한다. 웹 Docker 빌드 컨텍스트를 유지하기 위해 웹 사본을 포함하고 일치 검사를 수행한다.

## 입력·호환성

ONNX bundle, 128×128 uint8 RGB, 중심 좌표, 정규화 및 출력 스키마는 그대로다. ROI는 후보 중심의 선택 범위로 해석하고 128px 문맥은 실제 원본에서 읽는다. 기존에는 ROI 경계를 원본 경계처럼 취급해 64px 안쪽까지 제외했다. 사진 자체의 가장자리는 계속 제외하며 패딩/중심 이동을 암묵적으로 도입하지 않는다. 전처리 이력에 roi_policy/edge_policy를 추가한다. 기존 결과 파일과 프로젝트 스키마는 바뀌지 않는다.

페이지 추적은 접촉이 없을 때 반경 6px 안에서 마스크 IoU 0.6 이상인 명확한 단일 이동을 찾는다. 다른 성분의 경쟁 점수가 최상위의 85% 이상이면 모호함을 유지한다. 이동한 reference는 연결 선택에만 쓰며 출력 마스크에는 원본에서 관측된 픽셀만 포함한다. 빈 페이지를 채우거나 먼 결함으로 뛰지 않는다.

BPD 모델 정확도와 원본 경계 입력 정책의 학습/평가는 [sic-xrt-ml #47](https://github.com/CrystalVision-Lab/sic-xrt-ml/issues/47)에 분리했다. 새 모델을 소비하려면 manifest/schema/edge_policy/모델 SHA256/구버전 호환성을 확인한다. 여기서는 모델을 재학습하지 않았고 recall 향상을 주장하지 않는다.

## 실제 원본 재현 (비공개 로컬 artifacts)

사용자가 지정한 로컬 2D/3D 폴더를 읽었다. 데이터/스크린샷/모델은 Git에 추가하지 않았다.

- 12,349×12,273 JPG: 준비된 원본 픽셀 캐시를 사용한 분석 14.46초. 후보 3000 → 분류 2946 (BPD 245, TED 1398, TSD 1303), 가장자리 패치 부족 54. 사용자 화면과 수량 일치. 정량 모델 평가가 아닌 소비자 동작 재현이다.
- 158페이지 N119 uint16 TIFF: 사용자 화면의 41페이지 위치에서 전후 모두 28페이지를 연결했다. 51페이지 분기 모호함, 22페이지 접촉 없음에서 멈췄다. 이 사례의 자동 추적 개선을 주장하지 않는다. 원본 파일 size/mtime 보존 확인.
- 실제 Qt Direct3D11 화면: 첫 실행, 가이드, 2배속 추적, 완료 표면, 원본 직교 비교, JPG 결과를 1440×900 및 핵심 화면 1100×700에서 촬영/점검. QML 경고 없음. 작은 화면의 단면 3열 겹침을 축 탭으로 수정했다.
- 최초 별도 JPG 검증 스크립트는 앱의 준비된 픽셀 캐시를 생략해 JPEG 영역 읽기를 반복했다. 해당 검증 프로세스를 종료하고 정상 앱 캐시 경로로 재실행했다. 이 실패 시간은 제품 성능 측정에 사용하지 않았다.

## Wafer Map

동일한 합성 2946 후보, 20회 이동, 캐시가 준비된 상태의 중앙값: 22.19ms → 3.95ms. 좌표를 원본별 배열로 일괄 변환한다. 최종 표시 경로 1282개와 JPEG decode 1회를 유지했다. 임상/실제 데이터 전체 성능이나 모든 하드웨어의 배속 보장은 아니다.

## ImageJ 비교 근거

[ImageJ 3D Viewer](https://imagej.net/plugins/3d-viewer/)는 스택 볼륨, 표면, 직교 단면을 표시한다. [Orthoslices](https://imagej.net/plugins/3d-viewer/orthoslices)와 같은 축별 원본 비교 개념을 기존 앱 Volume API에 연결했다. Java 3D 플러그인 자체를 내장하거나 동일 결함 판정 엔진으로 간주하지 않는다.

REA 6.4.0 inspect-artifact로 기존 pinned ij-1.54p.jar를 재확인했다. evidence ev_22920cb3e2997b4e8ec014ce8d7c004c0e62ee24626d10125a59728db792a770. REA JEB 엔진은 미설정이며 심층 디컴파일/3D Viewer 플러그인 분석 완료를 주장하지 않는다. 원시 출력은 ignored artifacts에만 보관한다.
