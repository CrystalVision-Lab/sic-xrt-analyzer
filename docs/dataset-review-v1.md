# 전체 웨이퍼 점 라벨 검수 창

독립 검수 창으로 실행하며 기존 Analyzer의 실행 상태·원본·학습 분할을 변경하지 않습니다.

```powershell
python -m sic_xrt_analyzer.review_app --workspace <annotation_workspace v2> --candidates <candidate_workbench v1> --session <독립 검수 폴더>
```

viewer 의존성과 Qt 런타임이 필요합니다. 원본 등록에서 같은 SHA-256인 풀어 둔 파일 참조를 선택하고,
실제 사용할 원본의 해시 및 파일 상태도 확인합니다. ZIP만 있으면 원본 영상의 풀어 둔 복사본이
필요하다는 안내를 표시합니다. 실제 사용한 원본이 바뀌면 읽기와 직접 확인 체크를 보류합니다.

선택 입력 `--review-plan <계획 폴더>`는 Data Tools의 review_priority_plan v1을 소비합니다.
두 작업 해시·항목 ID·중복·개수를 검증하고 첫 목록을 진단 표본과 오류 항목으로 제한합니다.
전체 항목 메뉴로 기존 목록을 볼 수 있습니다. 결정 기록·원래 제공자 라벨은 그대로 유지하며,
표본 확인 완료를 선택하지 않은 항목의 승인 또는 데이터셋 전체 완료로 표시하지 않습니다.
관련 계약: https://github.com/CrystalVision-Lab/sic-xrt-data-tools/blob/feat/11-review-plan/docs/review-priority-v1.md

웨이퍼 1~9 및 3D, 전/후, 제공자/자동 출처, 미검수/보류/확인/수정/제외로 필터합니다.
한 번에 100개 항목만 표시하며 원본과 좌표 표시 패치를 나란히 보여 줍니다. 원본에서 최대
512×512를 부분 읽기하며 좌표는 원본 기준이고 EXIF 방향을 적용하지 않습니다. uint8은 그대로,
다른 dtype은 보기 목적의 1~99 백분위 대비를 적용합니다. 3D는 입력의 실제 프레임을 읽습니다.
원본 dtype/값이나 주석 좌표는 저장 과정에서 바꾸지 않습니다.
오른쪽 패치의 검은 테두리를 둔 노란 십자가는 중심이 원본 주석 좌표입니다.
중앙 8픽셀 공간은 표시로 덮지 않아 대상 결함을 볼 수 있습니다.

1. 실제 확인한 사람 이름을 입력합니다. 표시 검수자 양희승은 실제 주체 입력을 대신하지 않습니다.
2. 원본·좌표를 확인하고 큰 종류 또는 근거가 확인된 세부 문자를 선택합니다.
3. 직접 확인 체크 후 기존 라벨 확인 또는 선택 종류로 저장을 누릅니다.
4. 불확실하면 이유를 적고 보류합니다. 후보가 대상이 아니면 제외로 기록합니다.

자동 후보는 처음에 종류 미선택이며 이미지 읽기가 실패하면 직접 확인을 활성화하지 않습니다.
종류를 선택하지 않거나 직접 확인하지 않고 확정할 수 없습니다. 제공자 종류와 다른 종류는
수정으로 기록합니다. 이력은 덮어쓰지 않고 새 결정으로 누적하며 재시작하면 최신 결정을 복원합니다.
이미 확인된 항목을 다시 볼 때도 직접 확인 체크는 초기화됩니다. 여러 검수 창의 동시 기록은 지원하지 않습니다.

산출물 review_decisions_session v1 / decisions.jsonl 계약은
[Data Tools 계약](https://github.com/CrystalVision-Lab/sic-xrt-data-tools/blob/feat/9-review-decisions/docs/review-decisions-v1.md)을 따릅니다.
참조·해시·좌표·이력 검증과 학습용 정답 확정 준비 상태는 Data Tools CLI로 별도 검사합니다.
다른 저장소 내부 코드를 가져오거나 학습을 실행하지 않습니다.

이 화면은 기존 점과 대비 후보의 검수입니다. 누락된 새 점·영상 전체의 완전 주석 범위·BPD 전체
선·전후 동일 결함·3D 경로·스케일을 확정하는 화면은 아직 아닙니다. 세부 종류를 밝기만으로
판단하거나 주석 없는 영역을 정상으로 취급하지 않습니다. 기존 점을 전부 확인해도 전체 데이터셋
또는 물리적 정답·전문가 검수가 완료된 상태로 표시하지 않습니다.
