# 프로그램 업데이트 — Issue #123

## 사용자 흐름

최초 한 번은 배포 사이트의 0.1.1 설치 프로그램을 다운로드하여 기존 0.1.0을 업데이트한다. 0.1.0에는 앱 업데이트 기능이 없으므로 해당 버전 자체에 알림이 생기지는 않는다.

0.1.1부터 시작 3초 뒤 백그라운드에서 배포 서버의 새 앱 버전을 확인한다. 새 버전이 있으면 우측 상단에서 알리고, 도움말 → 프로그램 업데이트에서도 직접 확인할 수 있다. 자동 다운로드·강제 설치는 하지 않는다.

0.3.0부터 **업데이트** 버튼 하나로 다운로드·검증·기존 위치 적용·자동 재실행을 연결한다. 최초 설치는 일반 설치 프로그램을 사용한다.

1. 다운로드: 설치 파일을 스트리밍으로 내려받아 크기·MZ 형식·SHA-256을 확인한다.
2. 설치 준비: 배포 상태와 SHA를 다시 확인한다. 기존 프로젝트 저장/계속/취소, ROI 변경과 검수 초안 확인 절차를 통과해야 종료한다. 진행 중인 작업은 설치를 막는다.
3. 정상 앱 종료와 worker 정리 후 현재 실행 파일의 설치 위치로 Inno Setup을 무인 실행한다. 설치 완료 후 앱을 자동 실행한다. 원본·프로젝트·모델과 사용자 설정은 유지한다.

기존 0.2.0의 종료 후 설치 호출은 새 설치 파일의 검증된 캐시 handoff로 처리한다. 초기화 중 setup 자기 재실행은 지원되지 않으므로 별도 SHA 검증 보조 프로세스가 이전 setup 종료를 기다린다. 자세한 계약과 독립 실사용 시험은 [연결 작업 흐름](../desktop/CONNECTED-DEFECT-WORKFLOW.md)을 따른다.

소스로 실행한 개발 앱은 설치 파일 다운로드까지만 제공한다. 개발 체크아웃을 설치 프로그램으로 변경하지 않는다. 자동 설치 연결은 Windows frozen 앱에서만 제공한다. 실패·취소·오프라인 상태에서도 기존 Viewer를 계속 사용할 수 있다.

## 버전·배포 계약

기존 공개 GET /portal-api/releases의 xrt_app_release/v1, PUBLISHED, windows-x64, GPL-3.0-only, 승인 상태와 동일 revision의 source_archive를 확인한다. 현재 설치 버전보다 높은 버전만 표시하며 기본은 연구용 BETA 포함이다. 설정에서 STABLE만 선택할 수 있다. 공개 앱 파일 확인에는 연구원 인증키를 보내지 않는다. 모델 업데이트는 기존 AI 모델 관리·서명된 모델 계약을 유지한다.

0.3.1부터 기본 주소는 고정 Funnel HTTPS `https://pc1.tail23f008.ts.net`이다. 기존 설정의 유효한 `*.trycloudflare.com` 주소는 이 주소로 옮겨 저장한다. 사용자가 별도로 지정한 다른 HTTPS 서버는 유지한다. 현재 PC의 기존 설치 앱은 설정을 고정 주소로 바꾼 뒤 다시 실행해 새 버전을 받을 수 있다. HTTPS origin만 허용하며 인증값·경로·query·비표준 port를 거부한다. URL은 고정 API 경로와 UUID로만 만들고 HTTP redirect를 따라가지 않는다. payload의 파일 경로/URL을 실행하지 않는다.

현재 앱 설치 파일에는 Authenticode 코드 서명이 없다. HTTPS와 공개 SHA는 전송 무결성 확인이며, 서버가 침해됐을 때 배포자의 암호학적 신원을 별도로 증명하는 기능은 아니다. 업데이트용 실행 파일 서명·키 고정 정책은 후속 배포 단계다.

## 캐시·운영

Qt AppLocalDataLocation/app-updates를 기본으로 사용한다. 현재 사용자 전용 폴더로 운영한다. SIC_XRT_APP_UPDATE_DIR 환경변수로 D 드라이브의 전용 폴더를 지정할 수 있다. 실제 디스크 여유를 확인하고 최대 3 GiB 파일만 수신한다. 메타데이터는 1 MiB/100개 이하로 제한한다. 다운로드·검증은 GUI thread 밖에서 처리하고 진행률 알림은 0.1초 간격으로 제한한다.

취소/오류 시 partial 파일은 제거한다. 정상 캐시의 기존 기록 한 개만 다음 다운로드 시 정리하고, 같은 SHA 파일은 재검증하여 재사용한다. 비정상 종료로 남은 .part는 설치·실행하지 않으며 별도 전용 캐시 정리 대상으로 취급한다. 설치 직전 다운로드 당시 파일을 다시 해시 검증한다. 파일 철회 시 설치 준비를 거부한다.

## 검증

25개 앱 업데이트 검사 PASS: 같거나 낮은 버전, BETA/STABLE, 잘못된 origin/manifest, 다운로드 변조·누락·과다 수신·실행 형식, redirect, 철회, 취소, 캐시 재사용/손상 복구, 백그라운드 확인·명시적 다운로드, 오프라인, 종료 후 설치 handoff와 마지막 변조 확인, 실제 Main.qml의 프로젝트·검수 초안 취소 보호. 기존 QML/TIFF 검사와 함께 28 PASS. 설치 실행은 테스트에서 프로세스 호출을 기록해 검증했으며 사용자의 기존 설치를 QA용으로 덮어쓰지 않았다.

최종 frozen 앱의 실제 HTTPS 조회 PASS, 공개 서버에서 0.1.1 설치 파일 전체 스트리밍·SHA 검증 PASS. 최종 게시 정보와 SHA는 [배포 결과](RESEARCHER-UPDATE-122.md)를 참고한다.
